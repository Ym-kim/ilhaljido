# Traveler Notes 운영 가이드

## 목적

`/moments`를 에디터의 여행지 소개와 가입자의 실제 체류 리뷰가 함께 쌓이는 단일 섹션으로 운영한다. 초기에 회원 후기가 적더라도 가짜 후기·평점·작성자를 만들지 않고 `에디터 소개`를 명확히 표시한다.

## 공개 유형

- `editorial + introduction`: Wakation 편집팀이 공개 정보와 기존 도시 가이드를 바탕으로 작성한다. 직접 다녀온 후기처럼 표현하지 않는다.
- `member + review`: 로그인 가입자가 실제 체류 경험을 제출하고, 운영자가 공개 전 확인한 글이다.

두 유형은 카드와 상세 상단에서 항상 구분한다.

## 가입자 제출 흐름

1. 가입자가 `/moments/submit`에서 로그인한다.
2. 여행지·시기·여행 방식·본문·업무 팁과 선택 사진 링크를 제출한다.
3. `/api/moments`가 로그인 세션, 길이, URL, 사진 권한 동의를 검증한다.
4. 신규 DB 없이 기존 `applications` 테이블에 `job_type=traveler_note`, `status=pending`으로 저장한다.
5. `/admin`의 `여행자 노트` 필터에서 검수한다.
6. 필요한 경우 계정 이메일로 수정·사진 권한을 재확인한다.
7. 공개 승인된 글만 `src/lib/moments.ts`에 `sourceType: 'member'`, `format: 'review'`로 옮겨 배포한다.
8. 작성자가 수정·삭제를 요청하면 공개 데이터와 원 제출 기록을 함께 처리한다.

제출 즉시 자동 공개하지 않는다. 현재 단계에서는 Supabase migration과 공개 CMS를 추가하지 않는다.

## 에디터 소개 추가

`src/lib/moments.ts`의 `TRAVELER_NOTES`에 다음을 모두 채운다.

- KO·EN·JP 제목, 요약, 본문, 업무 메모, 출발 전 확인사항
- 로컬 저장 이미지와 3개 언어 alt
- 실제 여행지와 일치하는 `destinationSlug`, 숙소 앵커
- `sourceType: 'editorial'`, `format: 'introduction'`
- 게시일과 에디터 소개 고지

`npm run audit:traveler-notes`와 전체 빌드를 통과한 뒤 공개한다.

## 회원 리뷰 공개 기준

- 실제 방문 시기와 여행지가 일치하는지 확인
- 광고·협찬·대가성 여부 확인
- 숙소·식당·교통의 운영 상태와 사실 단정 최소화
- 개인 연락처, 얼굴, 차량번호 등 개인정보 제거
- 사진의 촬영자·게재 권한 재확인
- 안전·치안·비자·의료를 개인 경험 하나로 일반화하지 않음
- 과도한 편집 없이 작성자의 좋은 점과 불편한 점을 함께 보존

## 상태 해석

- `pending`: 검수 대기
- `contacted`: 수정 또는 권리 확인 중
- `confirmed`: 공개 승인. 코드 데이터 반영 후 배포 필요
- `cancelled`: 미게시 또는 작성자 철회
